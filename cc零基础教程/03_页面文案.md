## P24 技巧1：出错了怎么办

【眉标签】PART 04 · 技巧 01 / 12
【主标题】看不懂报错？
这样处理

【正文】
第一次遇到报错，几乎所有人都慌。其实不用。

【三步处理法】
STEP 01　不要自己看报错
直接把报错信息复制给它，说：「这是什么问题，怎么解决？」

STEP 02　让它自己 debug
说：「你帮我找找哪里出了问题，然后修复它。」

STEP 03　如果反复修不好
新开一个对话，重新描述你要做的事，从头来过。
有时候对话太长，它已经「绕进去」了。

【底部小字】报错不是失败，是它告诉你「这里需要注意」。

## P25 技巧2：Token & 费用意识

【眉标签】PART 04 · 技巧 02 / 12
【主标题】为什么越聊越贵？
怎么省钱？

【核心概念区块】
什么是 Context 窗口？
每次对话，它能「记住」的内容是有上限的。
对话越长，它处理的内容越多，花费越高，而且超出上限后会开始「忘事」。

【省钱三招】
01　任务完成后开新对话　　不要一个对话聊到底
02　用 CLAUDE.md 存背景　　让它不用靠对话记住你的项目信息
03　复杂任务用 Plan Mode　第一步先规划，避免走弯路反复修改

## P28 技巧5：Plan Mode

【眉标签】PART 04 · 技巧 05 / 12
【主标题】动手之前
先让它想清楚

【正文】
直接让它动手，往往改着改着就走偏了。
Plan Mode 让它在执行之前，先把计划列出来给你看。

【怎么用】
在你的需求前面加上：「先不要写代码，列一个执行计划给我看。」
确认计划没问题，再说：「好，开始执行。」

【为什么重要】
你看一遍计划，几秒钟。
它走弯路，可能要花你几十分钟来回修。

---

## P29 技巧6：权限 & 安全意识

【眉标签】PART 04 · 技巧 06 / 12
【主标题】它能做很多事
你要知道边界在哪里

【正文】
Claude Code 可以读写你电脑上的文件，可以执行命令。
这意味着：你要清楚你在让它做什么。

【几个基本原则】
不要在重要文件夹里随意让它「自由发挥」
执行前看一眼它的计划，确认你理解它要做什么
不确定的操作，先问：「这个操作会影响哪些文件？」

【底部小字】信任，但要验证。这不是不信任它，是对自己的数据负责。

## P30 技巧7：Git管理代码

【眉标签】PART 04 · 技巧 07 / 12
【主标题】后悔药
每次大改前先存档

【什么是 Git？】
给你的代码拍「快照」。
随时可以回到任何一个历史版本。

【为什么用 Claude Code 时特别需要它？】
AI 一次改动可能动十几个文件。
改出问题，如果没有 Git，你可能不知道改了什么，也没法还原。

【只需要记住两个操作】
git add . && git commit -m "说明"　　　存档（快照）
git checkout .　　　　　　　　　　　　还原到上次存档

【习惯】
每次让它做大改动之前，先 commit 一次。
