PART 04 · 技巧 01 / 12
看不懂报错？
这样处理
第一次遇到报错，几乎所有人都慌。其实不用。
STEP 01
不要自己看报错
直接把报错信息复制给它，说：「这是什么问题，怎么解决？」
STEP 02
让它自己 debug
说：「你帮我找找哪里出了问题，然后修复它。」
STEP 03
如果反复修不好
新开一个对话，重新描述你要做的事，从头来过。对话太长，它已经「绕进去」了。
STEP 04
截图发给其他 AI 排查
把报错截图丢给 ChatGPT / Gemini 问原因，多一个视角，往往能找到盲点。
PART 04 · 技巧 02 / 12
为什么越聊越贵？
怎么省钱？
什么是 Context 窗口？
每次对话，它能「记住」的内容是有上限的。对话越长，处理的内容越多，花费越高，超出上限后会开始「忘事」。
省钱 01
任务完成后开新对话，不要一个对话聊到底
省钱 02
用 CLAUDE.md 存背景，让它不用靠对话记住项目信息
省钱 03
复杂任务用 Plan Mode，先规划，避免走弯路反复修改

用语音输入，把你想要的一口气说出来——比打字快3倍，而且更自然。

让它永远记住你是谁、在做什么
每次开新对话，它对你的项目背景一无所知。
CLAUDE.md 解决这个问题：写好之后，它每次启动都会读。

PART 04 · 技巧 05 / 12
Plan Mode
动手之前一起想清楚
直接让它动手，往往改着改着就走偏了。Plan Mode 让它先把计划列出来给你看。
怎么用
方式一：输入 /plan 启动 Plan Mode，直接进入规划状态
方式二：在需求前加：「先不要写代码，列一个执行计划给我看。」
确认计划没问题，再说：「好，开始执行。」
你看计划的时间
几秒钟
它走弯路的代价
可能要花你几十分钟来回修
PART 04 · 技巧 06 / 12
权限 & 安全意识
每次 CC 要执行操作，它会弹出确认——你有三个选择：
选项 1
Yes  ·  这次允许
选项 2
Yes, don't ask again  ·  永久允许这类操作
选项 3
No  ·  这次拒绝
⚠️ 危险模式：bypassPermissions
跳过所有权限确认，CC 直接执行任何操作。
别名：--dangerously-skip-permissions（YOLO 模式）
只在隔离的容器或虚拟机里用，绝不用在你的主电脑上。
PART 04 · 技巧 07 / 12
Git & Commit
后悔药，每次大改前先存档
什么是 Git？
给你的代码拍「快照」
随时可以回到任何历史版本
为什么 Claude Code 特别需要？
AI 一次改动可能动十几个文件
改出问题，没有 Git 很难还原
存档
「git 一下」/ 「帮我把现在的进度 commit，备注是 [你做了什么]」
还原
「帮我还原到上一次存档的状态」
习惯：每次让它做大改动之前，先 commit 一次。
PART 04 · 技巧 08 / 12
不要重复造轮子
先问有没有现成的
你想做的东西，大概率已经有人做过了。在让它从头写之前，先问一句：
「我想做 [你的需求]，有没有现成的库或工具可以直接用？」
好处 01
现成的方案经过验证，更稳定
好处 02
不用从零写，省时间省 Token
好处 03
这是真正的程序员思维：先找，再造
PART 04 · 技巧 09 / 12
Skill & Tool：扩展它的能力边界
Claude Code 的能力不是固定的。Skill 和 Tool 让你可以给它安装新的「技能包」。
Skill
预设好的工作流，一句话触发。
比如：/deep-research 帮我研究 XX 话题
Tool
让它可以使用的具体工具
比如搜索、代码执行、文件操作
先用好内置功能。有了「这件事如果能自动化就好了」的场景，再来探索社区里有没有现成的 Skill。
PART 04 · 技巧 10 / 12
MCP：接入外部服务
让它连接你的世界
MCP（Model Context Protocol）让 Claude Code 可以连接外部工具和服务。
操控浏览器
让它帮你自动填表、抓取数据
连接数据库
直接读写数据，不用手动导出
接入 Notion
让它直接操作你的工作文档
建议：有了基础使用经验再来碰这个。先用好基本功能，MCP 是锦上添花。
PART 04 · 技巧 11 / 12
Hook：设定触发条件
让它自动运行
Hook 让你可以设定：「当某件事发生时，自动执行某个操作。」
每次保存文件后
自动运行代码检查
每次对话结束后
自动把摘要写入笔记
每次提交代码前
自动做格式整理
进阶功能。用熟了基本操作，有了「要是每次自动做就好了」的感受，再来设置。
