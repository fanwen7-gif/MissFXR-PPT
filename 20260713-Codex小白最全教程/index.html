第 1 章 · 是什么

Codex 整体介绍

Codex 是什么、能做什么

01 · Codex 能完成的，不只是“写代码”

核心能力

🛠️ 创建与修改 写网页、改文件、修问题、调整已有项目。
🔍 研究与分析 搜索资料、读取文档、整理信息、形成结论。
🎨 内容与视觉 生成文案、图片、网页素材，并继续修改。
⚙️ 操作与自动化 使用浏览器和桌面软件，让重复工作自动运行。
先把它理解成“能进入工作环境的执行者”，而不是一个更会聊天的搜索框。

01 · 你定义结果，Codex 推进任务，你根据证据验收

协作原理

🗣️ 你
说清想得到什么：目标、背景、限制和完成标准。
🤖 Codex
进入环境并执行：读文件、调用工具、修改、运行和检查。
🔍 你
查看证据：修改差异、运行结果、测试和最终成品。
🤝 双方
继续调整：补充信息、纠正方向，直到满足完成标准。
01 · 四种入口共享工作方式，但能力并不完全一样

4 个入口

⭐ 桌面应用（App）推荐 规划、审查、长任务和多任务协作；小白最容易建立全局视角，最推荐从这里开始。
命令行 直接在终端处理本地项目；适合已经习惯终端的人。
编辑器 边写边改、紧贴当前代码；适合开发过程中的即时协作。
云端 把任务放到托管环境中运行；运行环境与本机并不相同。
入口不是皮肤差异：运行位置、可用工具和适合的任务都可能不同。

选模型

简单、明确、需要快速反馈

优先速度和顺滑度

02 · 权限不是“全开”或“全关”

权限

给完成任务所需的最小权限；越难恢复、越影响外部，越需要停下来确认。
02 · 说做完了要查证据，报错了就粘原文

验收和报错

验收 · AI 说做完了
Codex：「已完成：首页三张图已压缩替换，加载 4.2 秒 → 1.8 秒」

人做三步检查

  • 看改了什么——是不是只动了图片文件
  • 自己打开一次——图清不清楚、版有没有乱
  • 对最初要求——「压缩但不糊」做到没有
报错 · AI 卡住了
Codex：「运行失败：Cannot find module 'sharp'（找不到模块）」

人这样下指令

你：「这是报错原文。找到原因并修复，修完重新运行，把成功结果给我看。」

要点：报错别自己概括，整段粘原文；要求「修复＋重跑验证」，不是只让它解释。

02 · 好提示词，不是长，而是说清四件事

提示词

目标想得到什么
背景项目、受众、现状
限制哪些不能动
完成标准什么证据算做完
模糊版本

帮我把这段修改想法整理成发给设计师的说明，语气友好点，别太长。

场景、优先级、哪些不能替我拍板，全靠它猜。

清晰版本

目标整理成设计师能直接执行的界面修改说明。
背景改首页首屏，明天过评审；是微调不是重做。
限制别替我拍板，别扩出这轮范围外的新需求。
完成标准4–6 条按优先级排，每条写清改哪里、为什么。

提示词的任务不是“显得专业”，而是减少 Codex 对结果的猜测。
02 · 小任务直接做，复杂任务先规划

计划模式 Plan mode

直接执行

目标清楚，范围很小

  • 改一处明确内容
  • 读取和总结文件
  • 修复一个具体问题
先用计划模式 Plan mode

背景复杂，存在多种路径

  • 需要先理解陌生项目
  • 会改动多个模块
  • 验收方式还不清楚
好计划必须同时写清：做什么、按什么顺序、每一步怎样验证。
02 · 记忆管你的偏好，AGENTS.md 管项目的规矩

记忆和 AGENTS.md

内容适合放什么不要把它当成什么
记忆个人偏好、长期背景、常用习惯不能替代必须遵守的项目规则
AGENTS.md项目约定、命令、目录规则、验证要求不要写成百科全书
只用一次
留在当前任务：不用为了一句话改项目规则。
每次遵守
写进 AGENTS.md：它已经成为项目长期约定。
个人习惯
说一句「记住」：让它进记忆，换个项目也认你。
沉淀不是把所有内容都存下来，而是把稳定、重复的部分放对位置。
02 · 反复在做的事，做成技能

Skill 和技能

技能（Skill）＝把一类任务的做法固定下来：步骤、模板、脚本和验收方式，下次一句话就能调用。

图片生成生成和编辑图片，适合内容与网页素材。
前端设计搭建和改进网页、组件与交互界面。
表格处理读取、分析、创建和验证电子表格。
演示文稿制作、编辑和检查幻灯片。
技能创建器把反复使用的方法做成自己的技能。
技能发现当你不知道有没有现成能力时，用它寻找。
按任务找技能，别按榜单装；也别为一个小要求就建一个。

图片输入

02 · Codex 是实习生，MCP 和 CLI 是它的门禁卡

插件和连通工具

不带卡时，Codex 只能动你项目文件夹里的东西和公开网页。想连上别的工具，看这三个角色的关系。

🧑‍💼
Codex · 实习生 听得懂任务、肯动手，但每栋楼都进不去。
→
💳
MCP／CLI · 门禁卡 MCP（Model Context Protocol）是通用一卡通，哪家 AI 都能刷；CLI 是对方自家发的卡。
→
🏢
对方工具 · 那栋楼 飞书、地图、支付宝……楼里装了读卡器才刷得进；装不装，对方说了算。
Codex 这头的能力是现成的；一个工具能不能连，取决于那头开没开接口。
02 · 有接口就直连，没接口就兜底

插件和连通工具

已开接口 · 装插件直连

办公类基本全接了

  • 文档：飞书文档、腾讯文档、语雀
  • 协作：飞书、钉钉、企业微信
  • 生活服务：高德地图、支付宝
还没开接口 · 用兜底

某书、某站、某某号官方没接

  • Chrome：用你登录好的账号操作网页
  • 电脑操作 Computer Use：替你点开和操作软件界面
不确定能不能接？把这句发给 Codex，橙色部分换成你想连的工具

「我想用 Codex 操作飞书：有没有官方工具？怎么连？连上能干哪些事、有什么限制？」

02 · 远程控制，是你从手机继续指挥 Codex

远程控制

查看
在手机上看线程、截图、终端输出、修改差异和测试结果。
判断
回答问题、批准下一步、改变方向或补充新的要求。
继续
文件、凭证和运行环境仍留在原来的电脑上，任务继续推进。
远程控制是“人远程管理 Codex”；电脑操作是“Codex 替人操作软件”。
02 · 先把流程跑通，再让它定时或批量执行

自动运行

跑通一次步骤、输入、输出和验证都明确。
→
定时任务按时间或节奏重复执行。
＋
codex exec接入脚本、批处理和持续集成。
自动化不是把不稳定流程定时重跑；它放大的是已经验证过的方法。
