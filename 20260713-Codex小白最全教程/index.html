PART 01 · 1.6 · 界面初识
打开先认这 4 块
看懂它，也顺手学会用
🧵 线程 Thread
看懂：一个任务一条对话线，来回和改动都记在这。
会用：一任务一线程；/fork 分叉、/compact 瘦身。
⌨️ 终端 Terminal
看懂：它跑命令（装依赖、跑测试）的地方，每步可见。
会用：出错别自己啃，把报错整段贴回去让它修。
🔀 Diff 面板
看懂：改动对照表，删红加绿。
会用：接受前必看；配合 git 存档、/review 复审。
🔐 权限提示
看懂：它动你的东西前先弹窗问你。
会用：三档 read-only / workspace-write / full，默认收紧。
看懂这 4 块 + 会用它们，后面的操作你基本都能对上号。

PART 01 · 1.8 · 差异化
第一次最常见的
4 个坑，先躲开
坑 01
目标给太大：一上来"帮我做个 App" → 它绕晕。第一个任务小到一句话能验收（改一行文案、修一个按钮）。
坑 02
没在项目里开 / 没给上下文：它找不到文件。在项目根目录打开，用 @ 把相关文件、报错贴给它。
坑 03
报错自己死磕：看不懂就卡住。把报错整段贴回去说"这是什么问题，帮我修"。
坑 04
权限一路全拒 / 全放：要么啥也干不了，要么裸奔。该批准的批准，危险操作再想想。
第一次没跑通，信心就断了——这 4 条躲开，基本都能一次成功。
PART 01 · 1.9 · 敢放手
敢放手三件套
权限 · 存档 · 审查
🔐 权限三档
read-only / workspace-write / full access。默认收紧，只在信任的仓库放宽。弹窗不是麻烦，是安全感。
💾 Git 存档
大改前先 commit = 游戏存档。AI 一次动十几个文件，改坏了一键回滚。
🔀 Diff + /review
删红加绿，接受前必看；/review 像 PR 一样复审。不看 diff 就接受 = 没看合同就签字。
🧵 一线程一任务
一个任务开一条线程；/fork 分叉、/compact 瘦身。别一条对话聊到死、越聊越糊涂。
四件事都是"敢把活交给它、又不至于翻车"的护栏——一页记住。

PART 02 · 2.1
提示词四要素
官方公式
要素要点一句话
Goal要结果，不要步骤说清你要什么，别替它规划怎么做
Context@ 相关文件 / 报错把上下文喂给它，别让它猜
Constraints约束、规范、禁止项先立规矩，划出边界
Done when可验证的完成标准什么算做完，你说了算
金句：没写 done when，就是在赌它对"完成"的理解和你一样。
PART 02 · 2.2 · 演示
同一件事，prompt 写法不同
结果常常差很多
模糊版 你以为说清楚了
我会给你一段我随手写的修改想法。帮我整理成一条发给设计师的说明，语气友好一点，重点说清楚我想改哪些地方，不用太长。
四段式版 目标 / 背景 / 输出 / 边界
目标我会给你一段零散的修改想法，请整理成一条能直接发给设计师的界面修改说明，让设计师读完就能抓住这轮最重要的修改重点、不用来回确认，也能判断该先做什么背景这次改首页首屏，明天要过内部评审；偏"微调"，不是整版重做输出整理成 4–6 条、按优先级从高到低；每条具体到"改哪里、为什么改"边界语气保持合作感、别像下命令；别把"我在纠结要不要改"写成已拍板；别顺手扩出这轮范围外的新需求
同一个任务，右边多花 20 秒把目标·背景·输出·边界补齐，返工就少一大半。
PART 02 · 2.3
Plan 先行
先规划，后动手
直接让它动手，往往改着改着就走偏了。/plan（或 Shift+Tab）让它先收集上下文 → 提澄清问题 → 出计划，你确认了再动手。
亮点技能：grill-me（反向面试）
它先采访你、挑战你的假设，把需求问清楚再干——史上安装量最高的 Skill 之一，而且不限于写代码，任何模糊需求都能用它先"面试"一轮。
你看计划花几秒钟，它走弯路可能要你花几十分钟来回修。
PART 02 · 2.4
AGENTS.md
给 AI 看的 README，短而准 > 长而泛
/init 一键生成。有效的写法以命令开头（安装命令、测试命令），不是长篇解释。
三层叠加：全局 ~/.codex  →  仓库根目录  →  子目录，越近优先级越高
写什么进去
安装 / 测试 / 构建命令
代码规范与约定
这个项目的已知陷阱
养成习惯
同一个错误犯两次
就写进 AGENTS.md
PART 02 · 2.5
记忆系统 Memories
规矩你写，笔记它记
AGENTS.md 是你写给它的规矩  ·  Memories 是它自己记的笔记：稳定偏好、工作流、技术栈、已知陷阱。
怎么开 · 怎么看
默认关闭：在设置或 config.toml 设 memories = true
打开 ~/.codex/memories/memory.md，看它的"日记本"
讲清边界
不可手动编辑 · 不跨机器 · 无团队共享
空闲后才后台合并 · 敏感信息要自查
开关在设置 / config.toml；单条线程用不用记忆走 /memories 命令——它不会因为你对话里说一句就去改配置。
口诀：该进 AGENTS.md 的，别指望记忆。

PART 03 · 3.2
为什么别人越用越稳
你却越用越乱？
病因诊断
把重复规则塞进每次 prompt  ·  把外部集成当成 skill  ·  把plugin 当成能力本身

PART 03 · 3.3
三分法：一句话记住谁管什么
Skill · 立规矩
SKILL.md 定义"怎么做事"。启动只读名称描述（约占 2% 上下文），匹配才加载；开放标准，跨工具通用。
MCP · 接外部
让它接上外部真实系统：数据库、内部 API、第三方服务，读写真实数据。
Plugin · 打包分发
把 skills + agents + hooks + 配置打包分发。@plugin、/ 或 $skill 调用，也可自然语言隐式触发。
Skill 立规矩，MCP 接外部，Plugin 打包分发。

PART 04 · 4.2
Subagent：分身术
派出多个分身并行干读重的活，各查各的，最后汇总给你。
适合
大规模调研
代码库摸底
多源信息收集
不适合
互相依赖的写操作
（会互相打架、越并行越乱）
原则：只做读重、可并行、互不冲突的任务。
