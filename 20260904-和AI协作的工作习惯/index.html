工具一步到位

用最好的工具，才分得清是用法问题还是模型问题。

「越是新手越应该一步到位，因为它可以帮我很好地判断究竟是我使用的问题、工具的问题，还是模型能力的问题。而当我一步到位最好的工具时，我就知道那应该是使用方法的问题。」

主力工具 Claude Code 和 Codex。

例子

换到 SOTA 工具后，AI at work 从每天 3 小时到 6 到 8 小时。

02

以终为始

目标和不能妥协的东西一次想清楚，路径推着走。

「实现路径是可以推着走的；怎么和现有的内容做耦合也是可以推着走的；但是我的目标和不能妥协的东西，是要一次性想清楚的。」

「要以终为始，因为工具无法帮你设定目标。」

写东西前先定读者、30 秒拿什么、用什么框架。

例子：这份清单就是这么问出来的；起标题工作流第一步是 AI 反向提问。

人和 Agent 分工

判断自己来，执行交给 Agent。

「判断要自己来，执行完全可以交给 Agent。当你的判断没问题，以及该有的细节都传递给 Agent 的时候，它的执行应该是能非常到位的。」

我和主 agent 是 CEO 和 COO，它有自己的下游工具和上下文。

「比事实层判断层更抬高一层的是：整体我们要以什么样的思路解决什么样的问题？我们当前是否在最优路径上？」

06

大项目分拆，判断和执行分开

「大项目分拆其实是分拆两层。第一层是大项目怎么拆成小项目：每一个独立的模块是什么，以及它们之间的耦合点和逻辑关系是什么，分拆是平面的。第二层是关键决策点：关键决策点是时间性的，前后有因果关系。」

例子

一次产品改版。先探数拿全基本信息做全局判断，第二次决策要不要改还是下一版迭代，第三次决策怎么砍，后面才是执行。

「前两次其实是在帮助你做判断，后半程其实是偏向于做执行。」「如果判断不清楚，执行是执行不清楚的。」

09

验收分阶段

「验收是分阶段的。」

内容是大纲、脚本、视频三次大验收，中间有子版本验收；代码是「先有大方案的验收，再到完整方案的验收，接着是对关键问题的确认，最后才是成品的确认。这里的每一个验收方法都不一样。」

「验收这件事分大点和小点，你要先想清楚怎么验收：有哪些关键点要验收？让谁去验收？有的我会让 Agent 去验收，有的我要亲自验收。」

要有学习和积攒工程能力的意识

「工程能力始终很重要，学习工程能力始终重要。」

a

用到哪学到哪，直接问 AI

「开发知识可以去学习了解一下，比如什么是构建、单测、编译、部署，不用系统学，用到哪学到哪，直接问 AI。」

让 AI 做每个工程动作时顺手问它为什么。

b

上线流程自己走几遍

「第一次基本上有了一个大概的模糊感觉；第二次有了确定性，心里基本有数了；第三次非常熟悉。」
